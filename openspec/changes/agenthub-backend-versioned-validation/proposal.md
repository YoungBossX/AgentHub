Automatically validate the built-in `demo-backend` using fixed platform-owned
Python syntax checks and HTTP contract tests in a fresh source copy. Reuse the
existing execution lease, cancellation, immutable event receipts and QA freshness
gates. Do not run target test files, package scripts or dependency installation.
Backend validation requires check/test, not a fictitious frontend build.

This is the first focused task in the user's requested local-workspace improvement
sequence. Evaluation coverage, review repair workflow, context accounting, UI and
long-term data management remain separate tasks after this one is verified.
