# Design

The user explicitly chose to retain the framework and change content only.
Use the existing Markdown outline and HTML hero plus five numbered sections.
Keep every existing style/script block byte-identical; content may replace
illustrations with real images and captions inside the existing containers.

README remains the project introduction and developer entry point, with existing
architecture/workflow/stack/module/startup sections. Use plain Chinese, link
source modules and detailed operating/evaluation documents, and distinguish
current capabilities from bounded historical measurements.

HTML remains a single static presentation with the same section IDs, grid/card
structures, palettes, breakpoints, theme controls and navigation. Refresh the
brand content and replace fake statuses/logs with actual screenshots. Images
link to full resolution and have Chinese alt text and provenance captions.

Prefer existing immutable native-run screenshots with recorded source hashes.
Current UI may display a read-only copy of real historical records, but cannot
represent a fresh model execution or active old preview. Original result images
remain explicitly dated. Do not use invented UI fixture states as native results.

Any displayed metrics retain version, denominator and test category. Native
planning/CLI, scripted fallback, model review, fixed validation and mock deployment
are separate. Do not claim PostgreSQL, multi-user IM, whole-Agent containers or
production deployment. Links must work in GitHub Markdown and a local static site.

Verification compares the before/after outline, section IDs, CSS/scripts and
existing layout wrappers; checks image hashes, local links and source claim
references; inspects actual light/dark HTML at desktop/tablet/mobile sizes.
