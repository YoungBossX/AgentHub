## ADDED Requirements

### Requirement: Evidence-grounded public project content
README and the root HTML presentation SHALL describe implemented capabilities
accurately, provide usable entry points and show real product screenshots.

#### Scenario: Content refresh within the existing design
- **WHEN** documentation is refreshed
- **THEN** existing README section order and HTML sections/layout/style/scripts remain intact
- **AND** wording and image content reflect verified source and dated evidence
- **AND** native, fallback, historical and illustrative evidence remain distinguishable

#### Scenario: Browsing the presentation
- **WHEN** the page is viewed in either theme at desktop or narrow sizes
- **THEN** screenshots and captions load and remain readable without horizontal overflow
- **AND** existing navigation/theme controls and local links remain usable

#### Scenario: Representative images without metadata jumps
- **WHEN** the public presentation shows a capability
- **THEN** a focused actual task, Diff or functional-interaction scene makes that capability readable
- **AND** image wrappers/captions contain no raw-image, provenance or metadata jump links
- **AND** concise captions explain visible behavior while repository metadata retains source dates and limits
- **AND** expired QA evidence is not presented as current acceptance and historical records remain unchanged

#### Scenario: Platform workflow is distinct from example business
- **WHEN** a visitor reads the homepage or README
- **THEN** task decomposition, multi-Agent execution, real Diff, review results and application preview form the main narrative
- **AND** contacts management is labeled as an example application rather than a platform capability
- **AND** the role directory and its settings use 协作 Agent wording without changing routing, selection or execution behavior
