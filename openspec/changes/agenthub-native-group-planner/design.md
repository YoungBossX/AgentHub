# Bounded native group planning

Build detached assignments using existing direct factories, preflight selected
profiles and targets, then send an ordered explicitGroupAssignments contract to
the existing configured Planner. Its actual frozen System Prompt and no-tool
policy remain in the transport. No-tool Claude planning also uses native safe
mode to disable ambient hooks/plugins and instruction discovery, preserving
the CLI's normal authentication and model selection. Windows resolves the
installed native npm executable without shell parsing and decodes UTF-8.
The bounded group CLI call uses low reasoning effort because roles/targets/order
are already selected and locked; its real content is still validated and used.
Restrict provider-visible targets to the group
and the selected Planner's declared scope. Native output must contain exactly
one task per ordered role/target assignment, including separately scoped reviews.
Validate paths, artifact types, intents, risk, commands and dependencies; retain
server-owned serial write/review dependencies and selected profile identity.

Apply native titles, file plans, acceptance criteria, validation expectations and
rationale to detached tasks. Persist tasks and the coordinator reply atomically,
with provider, prompt hash, memory and runtime evidence. Recheck selected profiles
after the call. Planner errors or invalid/non-task output fail explicitly; they
cannot silently substitute deterministic success. An unconfigured/disabled
built-in Planner retains the existing disclosed deterministic path.

Keep explicit_group_v1 as the execution identity so advisory coding reports do
not complete a selected reviewer, and scripted review remains read-only. Native
coordination source is separate from coding/review provider evidence. Execution
continues through current manual-start endpoints and runtime fences.
