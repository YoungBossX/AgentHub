# Budget boundary

Count application-managed final input, after provider rendering and native review
or MCP additions, with Unicode characters and UTF-8 bytes. HTTP Planner requests
include structured-output schemas; image bytes/base64 have separate count and wire
limits. This is a deterministic transport budget, not a model-token estimate.

Keep existing source selectors and their omission records. Do not trim frozen rules,
Skill snapshots, current user text or reference content at this final gate. If the
assembled input exceeds the fixed shared limit, reject before process/network
invocation. Show final totals, source inventory with explicit included/omitted
reasons and the non-additive nature of layer estimates. Historical receipts remain
bound to the exact rendered-input hash and are not recomputed as if sent today.

Persist prepared coding input accounting through the existing exact-generation
snapshot conditional update, and update it after native contract assembly. The
final launch boundary rechecks totals and hashes without provisional writes;
failed gates use the existing scope/ownership error path. Preparation does not
claim that a Provider has read the request or succeeded.
Planner payloads carry diagnostics outside serialized input to avoid recursive
accounting or changing user content. Expose receipts in execution/Planner details.
