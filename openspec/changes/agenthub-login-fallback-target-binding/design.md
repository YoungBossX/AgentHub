# Design

The adapter's explicit-target validation is correct. Fix new task construction,
not the adapter, by recognizing a creation action for a login page/form scoped to
the built-in demo. Keep copy/input/color/status/layout intent precedence and avoid
turning reviews, documentation, unrelated/external login requests, broad platform
work or unsupported authentication integrations into template mutations.

Persist the parser's target/text in built-in direct frontend task plans. Existing
registered targetId, safeTarget, planned file hints, original request, selected
Agent identity and access policies remain authoritative. Group construction reuses
that factory and preserves independent review/dependencies; native group planning
continues to replace semantic task content through its existing validated path.
Preserve the established English deterministic Orchestrator plan and its three
steps. Login creation is opt-in for direct/group parser calls; existing
Orchestrator dynamic-intent calls keep their previous behavior, including active
and external target selection. The final Orchestrator creation branch uses the same
bounded grammar in place of two substring checks; Chinese bounded requests also
reach its three-step plan, while compound authentication requests stay generic.
The creation grammar matches only bounded complete requests, optionally followed
by allowlisted language/check/changelog process notes used by the existing memory
rehearsal. Those notes remain in the original request and do not expand file scope
or claim checks/docs were executed. Additional integrations and compound feature
requests remain generic.
Do not patch historical plans/snapshots during retry or silently guess a
target in ScriptedMock. Unsupported targets remain failed without file writes.

Tests must cover persisted direct/group/Orchestrator bindings, known follow-ups,
negative parse/scope/external cases and actual engine recovery with a real Git
fixture. Run focused then full API checks. Real local acceptance uses an isolated
SQLite, existing setup dependencies and browser; retain honest failure history,
fresh fallback file/Diff/Preview results, source matching, refresh/restart and
same-Session modification. Any deliberately unavailable CLI or simulated failure
must be labelled; no fake real provider/model success. Preserve unrelated current
services and their frozen accepted source. Update docs and evidence before completion.
