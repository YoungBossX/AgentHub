# Design

The CLI runs from `apps/api` using the existing virtualenv. It requires a fresh output directory outside the AgentHub checkout and system roots, creates its own fixture repositories and SQLite database, and never deletes, resets, or overwrites an existing output tree. Git commits are fixture baselines only; the development checkout is not committed or pushed.

Each fixed case permits edits only to `src/domain.mjs` in its registered external Vite React target. The scaffold uses the domain function in React, but acceptance tests use dependency-free Node built-in assertions and do not require installing or starting Vite. No build or visual success is claimed. The evaluator lives outside the assigned target and its bytes, baseline files, prompt, and suite manifest are hashed before execution.

The harness creates a confirmed project rule and a new Session snapshot, persists a fixed coding Task, and uses `create_task_run` plus `RunWorker` for execution. This measures the coding execution path from a fixed plan; it does not exercise LLM planning, chat UI, multi-agent scheduling, preview, or deployment. Live mode uses only the existing CodexAdapter and never switches to a mock. Provider events prove the observed CLI turn; model/upstream identity is unknown unless directly reported.

Each case records the pre-run failing evaluator, actual elapsed attempt time, persisted run state, sanitized failure information, event identities, provider/assignment metadata, snapshot and prepared memory receipt, scope decision, Diff patch hash, post-run evaluator, and immutable-input checks. Passing requires a completed run, observed provider thread/turn completion, passing post-check, unchanged evaluator/scaffold, correct memory rule receipt, passed scope and a nonempty matching Diff confined to the allowed file. A green evaluator alone cannot turn a failed TaskRun into success.

Prepare-only results have no provider success rate. Live results use all selected cases as denominator, including preparation/runtime/evaluator failures. A run report is saved after each case and carries no inferred speedup, general success rate, or historical result substitution. Tests use explicitly identified doubles only to verify the harness's failure accounting and engine integration; their output is not live evidence.

Acceptance directly executes the fixed `node:test` module with Node 22.13+ permission flags, avoiding CLI test discovery and child-process access. It grants reads only to fixture/evaluator directories, grants no filesystem writes, requires the exact expected test/pass counts and zero failures, and hashes immutable files after the evaluator finishes. The Node permission model reduces accidental access; it is not a hostile-code sandbox and does not add production sandbox guarantees.
