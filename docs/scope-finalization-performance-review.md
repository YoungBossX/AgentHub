# 输出核验性能验收

日期：2026-10-08；`agenthub-scope-finalization-performance` 1.1 完成（本地未提交）。

实际会话的 517 文件快照在 cProfile 下触发 869,531 次路径状态读取，采样耗时
13.92 秒，主要开销是反复核对路径身份。完成流程还先计算临时 scope 判定，再在
持久化时重新采集一份完整快照。此前并行跑回归时观察到的 45–55 秒阶段耗时不能
当成当前空闲条件下的固定基线。

本项增加只接受 TaskRun ID 的 `validate_and_persist_task_run_scope`，在共享持久化
操作内部采集一次新鲜完整快照。采集前固定原始指标和基线，继续使用原有策略、
上下文、锁、worker 和指标 CAS；失败不能返回成功判定。完成流程同时要求本次
判定与持久化标记通过。原 `persist_scope_decision` 对调用方传入的成功/拒绝判定仍
重新采集并比对，避免旧判定直接授权成果。

`task_run_scope.py` 的字节哈希保持不变。普通/保护文件、Git 各层、重复稳定性
采集、HMAC、Windows 命名流/重解析点、大小写、描述符和硬链接核验均保留。
只读路径、非空 Diff、no-op、失败和代际提交围栏继续执行；功能完成契约仍为
`functionalAcceptance=not_evaluated`。

## 实测

同一台机器上，每版各新建一份 SQLite 和 Session，通过正常消息/任务 API 请求
两次按钮文案修改，显式脚本兜底；初始 Codex 失败为主动模拟，没有调用真实模型。
每对任务的 517 项基线内容指纹完全相同，所有脚本结果均有实际文件变化、非空
Diff、成功 scope 和完成记录。详见证据目录中的 `timing-comparison.json`。

| 指标 | 原流程 | 修复后 |
| --- | --- | --- |
| 第一次任务总耗时 | 19.640 秒 | 13.308 秒 |
| 第二次任务总耗时 | 21.420 秒 | 15.066 秒 |
| 两次任务平均总耗时 | 20.530 秒 | 14.187 秒 |
| scope claim 到判定的平均耗时 | 13.091 秒 | 6.707 秒 |
| 每次脚本任务的完成阶段完整快照 | 2 次 | 1 次 |
| 并行健康请求最大观测延迟 | 226.5 毫秒 | 205.4 毫秒 |

这两组固定任务的平均总耗时下降 30.9%，核验阶段下降 48.8%。样本只覆盖同机
两次顺序修改，不能推广为所有项目、所有文件数量或所有 Provider 的性能指标。
完整采集仍随工作量变化，性能剖析本身也有开销。

另外在回归负载下新建独立 Session，以实际 Edge/Vite 完成两次修改和预览更新：
`Timing first`、`Timing second` 均与生成页面一致，页面错误为空，截图已检查。
该组耗时包含预览并受测试负载影响，不混入上表。

正常关闭后重新启动同一 SQLite，Session、Message、Task、TaskRun 四类表的
完整有序行哈希保持一致；完成标记仍可读取，显式重开 Vite 后仍显示 `Timing second`。
此前原生 Agent 会话的 API 历史和 App 源码哈希与上一项冻结值一致。
