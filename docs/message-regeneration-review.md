# 消息重新生成验收

日期：2026-10-09；`agenthub-message-regeneration` 1.1 完成（本地未提交）。

## 行为与来源

普通回复和计划下新增“重新生成”。确认区说明：重新处理原请求及附件，使用当前
代码、上下文和 Agent 配置，可能创建并执行新的代码任务；原消息与成果保留，
已有文件修改不会撤销。这不是精确复现旧模型输出，也不是失败 TaskRun 的重试。
未完成的原计划、活动运行和审批等待继续使用原有任务操作，不被重新生成绕过。

后端从同一 Session 的回复/计划解析其真实用户请求，追加新请求，再进入原规划、
审批、Queue、Target Lock、scope 和完成判定流程。内容和引用上下文复制自数据库；
附件引用不可变原记录，支持再次生成及置顶新请求，不复制二进制、不重新绑定归属。
新请求和回复显示来源及状态。“新请求已生成”只指准备完成，代码结果仍以任务为准。

当前已完成的任务组汇总可“重新汇总”：沿用协调 Agent 的冻结配置及当前证据，
继续检查 owner、lease、输入指纹和权限。只新增解释，不重新执行编码任务。
旧汇总保留，最新身份随新汇总更新；失败汇总仍使用原有“重试汇总”。

## 并发、失败与重启

新增 Message.regeneration_json，使用现有 SQLite 增量初始化，旧消息默认为 `{}`。
普通创建消息接口不能设置这列。客户端 UUID 成为新消息的持久操作 ID；同一来源
重复发送此 ID 只返回已存在的操作，跨会话或不同来源重用被拒绝。Session 写事务
串行验证和准备；模型调用前释放事务，同会话同时准备的另一请求被拒绝。

浏览器在会话存储中保留尚未确认的操作 ID，遇到响应丢失先按 ID 查历史，再尝试
同一次操作。存储不可用时仅在当前页面内保留 ID。切换会话后的迟到响应只更新原
会话记录，不覆盖当前视图。没有 TaskRunEvent 的准备阶段也会刷新消息状态。

规划异常保存失败记录和已存在的部分计划，不回传原始异常文本、不隐式重发。
本地单 API 进程启动时将中断的请求准备标为失败，保留来源；不会自动恢复模型调用。
这是现有单用户、单 API 运行边界，不声称支持多个 API 进程共享同库的准备协调。

正常停止本轮自有 API，再通过正式入口启动新进程。操作
`e2bb09b6-806f-46fd-ab4f-8d59faf13bc5` 被标记为
`REGENERATION_PREPARATION_INTERRUPTED`，没有创建对应 Task，也没有自动模型调用。
重复提交仍返回原失败记录，浏览器刷新可见。此项为受控准备状态加实际重启，
不伪称自然崩溃复现。

任务、运行和源码在重启前后保持一致，只有受控中断操作的状态按设计变化。
