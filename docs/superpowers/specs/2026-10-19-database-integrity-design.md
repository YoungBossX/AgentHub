# 数据库完整性修复与 PostgreSQL 迁移前置设计

状态：2026-10-19，用户批准[实施计划](../plans/2026-10-19-database-integrity.md)，按 Native 方式在独立工作树实施；产品库尚未升级。
对应 OpenSpec：[`agenthub-database-integrity`](../../../openspec/changes/agenthub-database-integrity/proposal.md)，本阶段只有任务 1.1。

## 1. 目标和范围

用户要求先修复外键约束与事件序号并发，再推进 PostgreSQL；保留现有数据，
新数据、备份、临时文件继续放在 `E:\Docker`，清理不再使用的内容。

先完成 SQLite 完整性修复，再进行独立的 PostgreSQL 兼容与迁移专项。
本阶段保留 SQLModel、SQLite、三个 Adapter、现有 SSE 协议和执行权限。
不切换产品数据库，不安装驱动，不运行 PostgreSQL，不改 UI、Provider 或沙箱策略。
既有源数据库仍在原位置；不通过直接搬动数据库文件来满足新增数据存放要求。
产品库离线升级在实现及演练验收后执行，操作前必须明确目标、备份目录与停机窗口。

成功标准是数据库实际拒绝无效关联、并发事件不重复编号、SSE 回放仍完整，
并能通过固定迁移兼容旧库，保留每一条历史记录、原字段值和附件字节。

## 2. 已核对的事实

开发主树 `X:\Git_Clone\AgentHub`：`main` / `8392b7f`，有前一沙箱任务的未提交文档。
沙箱实现在独立 `codex/container-validation` 工作树，尚未提交或集成；不能覆盖或清理。

- Session SSE 使用 `created_at|UUID` 游标，而不是 TaskRun 局部 sequence。
  当前时间戳分配依赖 SQLite 写事务串行化；修复不能破坏这一语义。

   `quick_check=ok`。没有执行备份、DDL、seed 或业务数据写入。
   这是检查时的快照，正式升级须在独占维护期间重新核验，不替代完整性与数据保留验收。

## 3. 方案取舍

采用“连接强制约束 + 固定离线 revision + 事务内编号 + 数据库唯一索引”。
运行层阻止产生新问题，迁移层补齐旧结构，数据库约束防止绕过正常写入路径。

不采用只加 Python 线程锁：它不能保护另一个 API 进程或数据库连接。
不采用只加唯一索引并吞掉冲突：虽能拒绝重复写入，却可能让状态和事件失去对应关系。
不采用先换 PostgreSQL 再修复：会同时改变锁、时间、迁移和维护语义，难以定位回归。

## 4. 外键连接策略与业务事务

建立无产品库连接副作用的 SQLite 引擎配置入口，在每一个新物理连接、事务开始前设置
`PRAGMA foreign_keys=ON`，读取确认生效；不能在已有事务中尝试开启后假定成功。
应用和业务级测试/评测连接复用该策略，不使用影响所有第三方引擎的全局监听器。

运行时禁止关闭外键，也不为绕过约束增加级联删除或自动补造父记录。
API 遇到无效外键输入，应沿现有资源校验返回明确错误；数据库层仍保留最终防线。
检查真实创建流程的父子行 flush 顺序及删除路径，必要时明确先写父行、再写子行。
测试夹具也应创建真实父记录，不能通过测试专用关闭外键维持绿灯。

审计对象覆盖冻结定义中的所有外键，除 `foreign_key_check` 外，对旧表缺失的每个关系
执行显式反关联检查。空值继续遵守现有 nullable 语义，不扩展成所有业务字段非空。
发现孤立引用、空主键或未知结构时报告表/字段及数量，拒绝升级；不删除或修补历史行。

## 5. 固定迁移和旧库兼容

新增线性 revision `0002_database_integrity` 和独立冻结的 v2 结构契约。
v1 文件及既有 revision 保持不变；运行期识别器区分 v1 待升级、v2 current、
受支持无版本旧库与不兼容库。启动仅初始化空库或验证 current，不自动升级已有库。

迁移目标：

- 新增唯一索引 `ux_taskrunevent_run_sequence(task_run_id, sequence)`。
- 对精确识别、且确实缺失外键的历史表，按冻结定义重建并补齐约束；
  完整表不重建，当前源库只需索引变更及版本升级。
- 新空库和经历史兼容路径升级的库达到同一约束语义，不能在 v2 继续把缺失外键当作 current。
- 迁移前检查重复序号与非法序号。若存在，原样保留并拒绝升级，不重新编号、删除或合并。

仍只有受控 `db:migrate` 协调器可升级；禁止裸 Alembic/stamp 绕过维护租约与验证。
现有库升级须：独占维护、停写核验、WAL 一致备份、全旧字段/BLOB 摘要、隔离副本演练，
演练成功后才操作源库。备份目录必须新建且在 `E:\Docker` 的仓库外位置。

重建历史表遵循 SQLite 官方安全步骤：只对迁移专用连接在事务外关闭外键检查，
再显式开始受控写事务，创建新表、显式列投影复制、替换表并恢复固定索引。
不先重命名原表，不删除业务记录，不运行目标代码或 seed。
替换后在提交前执行全部预期关系检查、`foreign_key_check`、`integrity_check` 和旧值摘要比较；
提交后恢复并确认外键开启，销毁专用连接，业务连接不复用该连接。
若不涉及重建，不需要关闭外键。

不得直接给未知结构或含违规数据的库盖版本标记。故障注入必须覆盖复制、替换、索引、
验证和提交阶段；替换事务失败回滚，连接中断或提交结果不确定时停止自动恢复，
保留备份、阶段回执与实际版本供核对，不覆盖源库、不报告成功。
不提供破坏性自动 downgrade。保留“提交完成但回执失败”和“事务未提交”的区别。

## 6. 事件并发、状态原子性和 SSE

保持 `stage_task_run_event` 与 `append_task_run_event` 的职责：前者只暂存、不 commit；
后者在提交后通知订阅者。状态更新与其事件仍由同一事务提交或回滚。

在读取最大序号之前取得数据库写锁，持续持有到调用方事务结束。
SQLite 使用对对应 TaskRun 的固定无值变更 UPDATE 取得写事务所有权，
再读取该 run 的最大序号并插入事件。此 UPDATE 不改变 ID、状态、generation 或时间字段。
新建 TaskRun 的路径先按外键顺序 flush 必要父记录；已有写事务路径可重复调用锁入口。
不在 helper 中通过 rollback/commit 丢弃调用方已暂存的状态、审批或制品。

序号在锁内由已有最大值递增；唯一索引是最终防线。回滚不留下事件或已提交状态，
不承诺跨回滚/失败连续无缺口；历史 ID、sequence、created_at、payload 均不改写。
时间戳继续在写锁内按现有全局上界分配，保持旧游标格式、UTC 精度和分页顺序。

SQLite 锁等待必须有界。已有读快照无法升级时，不能在失效事务中重复 MAX/INSERT；
在持有该事务的业务入口明确回滚并返回可识别冲突，或仅重试可安全重放的完整数据库事务。
不自动重试 Provider、文件编辑、部署或其他外部副作用，不吞掉 IntegrityError 伪造成功。
审核所有事件生产入口的事务边界，覆盖先读后写、已持写锁和待 flush 父行三类路径。

并发测试使用独立连接及独立进程，不能只共享内存锁或单一 DbSession。
受控短事务竞争必须均能提交且序号不同；超时/回滚用例必须可重试且无部分成功。
还要验证不同 TaskRun 的交错提交、同事务多事件、先持锁者回滚、相同墙钟时间，
通过真实回放分页证明没有遗漏或重复，不能只检查最终行数。

## 7. 验收边界

在新的外部数据库/临时目录验证：

| 范围 | 必须通过的证据 |
| --- | --- |
| 连接与关系 | 多连接外键开启；孤立 insert/update 与仍被引用的父行 delete 被拒绝；正常创建/清理流程有效 |
| 旧库 | 空库、v1、无版本已支持历史库到 v2；缺失外键的旧表补齐；自引用/跨表关系和附件 BLOB 保留 |
| 拒绝条件 | 孤立引用、重复/非法序号、未知结构和活动运行时拒绝；无删行、盲 stamp 或自动覆盖 |
| 事务 | 跨连接/进程并发编号唯一；状态/审批/事件原子；回滚、锁超时和断开无假成功 |
| SSE | 旧游标仍可用；交错 TaskRun 的分页、断线恢复及高水位回放完整 |
| 生命周期 | WAL 备份、副本演练、重建故障、独占维护、版本验证与 seed 原设置保留 |
| 相邻流程 | 三个 Adapter、队列/Target Lock、审批/中断、真实 Diff 和预览路径未回归 |

测试通过既有 `pnpm test:api` 包装器使用新外部库，TEMP/TMP/TMPDIR 指向
`E:\Docker\agenthub-temp`；不让测试默认连产品库，不安装依赖。
实现后执行相关迁移/事件/生命周期回归、根检查和必要完整回归；
旧沙箱测试结果不能证明本专项修改通过。任务只在实际验收完成后勾选。

## 8. PostgreSQL 后续边界

前置任务验收后，按用户已确定方向另做 PostgreSQL 专项设计、计划和实施：

1. 保留 SQLite 默认兼容路径，增加可选 PostgreSQL + Psycopg 3；选择版本时核验当时官方支持，
   说明新增依赖后再安装。不更换 ORM、不增加 Redis/RBAC/WebSocket。
2. 抽离引擎初始化、schema 核验、事务锁、数据库时钟和维护互斥。
   保留 generation/租约/过期 worker 拒绝语义；不能把 `julianday` 简单替换成应用时间。
3. PostgreSQL 上须设计跨 TaskRun 的提交顺序与 SSE 游标保护；仅行级编号或 sequence 唯一
   不足以保证时间游标回放完整。不能照搬 SQLite 单写者假设或仅用本机文件锁保护远程库。
4. 新 PostgreSQL 数据卷、导出、备份、演练和临时文件全部落在 `E:\Docker`；
   明确专用本机容器/数据库及最小暴露，不动已验证镜像、其他容器和数据卷。
5. 停写后备份 SQLite，导入全新目标库；不覆盖已有 PostgreSQL 库。
   按列类型作明确可逆的兼容映射，核验逐表主键/行数/字段规范值、UTC 精度和 BLOB 哈希；
   不能只比较总行数或拿不同数据库的原始类型摘要直接判等。
6. 完成新库启动、旧 Session/附件/事件读取，以及新任务—Diff—预览—中断/重试验收后再切换。
   切换前保留 SQLite 原库；切换后有新写入时禁止直接切回旧库冒充无损回退，须另做反向迁移。

这些是后续验收边界，不代表 PostgreSQL 已接入或已经完成数据迁移。
