## 异常与修复

- 采集实现的独立审阅发现 MCP 脱敏包装冲突、提前终态丢失用量、Codex 正文识别和取消阶段
  误计耗时；先复现失败，再修复并通过 185 项相关回归，保留原有权限和所有 Adapter。
- 联系人第 1、8、9 次在 POST 创建成功、随后 GET 刷新失败时丢失已确认的新联系人。
  原第 1 次另建隔离目标，真实 Agent 修复为先解析真实创建回执、按 id 合并，再刷新；同时补充
  前后端空白姓名校验。原正式失败不改写，追加完整门禁及 28 项契约通过。
- 首版追加操作器把负例产生的坏数据带入下一视口，已保留失败日志并调整为两视口结束后再执行
  独立 API 负例。修订版先精确复现六项失败，再验证全部通过，未修改正式批次操作器。
- 后端第 5 次规划在 60 秒预算超时，未收到最终用量。相同需求和预算独立重发通过，根因仍未确认。
  QA 的其余低风险警告逐条保留，不通过降低门禁或修改只读目标测试来美化分数。
- 首次完整回归因 Windows 长临时路径出现两项隔离清理失败后停止，原文件仍在；使用 E 盘短临时根，
  相关 12 项和完整回归重跑通过。此为测试目录问题，不是已完成的一轮失败回归或数据丢失。
