# AgentHub 本地使用说明

AgentHub 当前面向本机单用户编程工作流。数据库、会话工作树和模型 CLI 均在本机，
网页提供对话、执行过程及成果查看。本文对应现有实现，原始设计要求的核对见
[个人项目交付表](local-project-delivery.md)，实测与限制见 [项目状态](project-state.md)。

## 本地 API 与预览边界

API 只接受 `127.0.0.1`、`localhost` 或 IPv6 回环 Host。浏览器来源必须是工作台
来源（默认端口 3000，或显式配置的 `AGENTHUB_FRONTEND_ORIGIN`）；预览端口不拥有任务控制权限。
会改变状态的请求还必须携带 `X-AgentHub-Control: local-workspace`，工作台会自动添加。
通过 Python、curl 或其他本地工具调用 POST/PUT/PATCH/DELETE 时同样需要添加该头。
这个公开标记用于强制浏览器预检，不是登录密码，也不代表多用户认证。
MCP 文档网关继续使用单独的执行绑定 Bearer 凭据，控制请求头不能代替它。

新建预览使用服务端固定的 Vite React 配置，只服务前端目录和必要的已安装依赖。
禁止额外目标拒绝路径、`.env*`、`.git`、`secrets`、凭据文件和越界链接；JS/CSS 导入同样受检查。
CSS 本地相对导入可用，远程/data/转义导入保守拒绝。缓存位于服务端临时目录并随预览清理。
不会加载项目自己的 Vite 配置；需要自定义插件、代理或特殊预处理器的项目不属于此固定预览配置。
运行中的旧预览需要停止后重新启动，才能采用新边界。

## 聊天与置顶上下文

### 配置与使用项目文档 MCP

打开 Agent 目录设置中的“MCP · 工具连接”。启用项目文档 MCP，选择“列出文档”和“读取文档”，
勾选默认使用它的前端/后端 Agent 或自定义 Codex 编码 Agent，然后保存。默认连接关闭。
“测试连接”会通过真实回环 HTTP 检查已保存配置的握手与工具列表，不会读取项目文档，也不证明模型实际调用。

兼容 Codex 的新运行会使用创建 TaskRun 时冻结的工具配置。可在消息中要求先查询 README/API 文档，
也可把这一工作方法保存为 Skill。执行过程 → 执行链路与制品状态 → MCP 工具调用，展示服务端实际执行记录、
参数、来源文件/哈希和有界结果。配置、连接成功、工具调用成功、QA 通过是不同证据。
Claude Code / ScriptedMock 当前保留原流程并显示不支持此连接。

首版只读当前分配目标的 README/docs；内置前端还可读取同工作树内显式关联的演示后端文档。
各文档目标的额外禁止路径同样生效；外部项目只读分配给运行的 checkout，不转读注册的宿主目录。
文档在启动边界冻结；后续文件修改不会改变该运行的文档快照。
每个文档不超过 16 KB、每次快照最多 16 文件/64 KB，每次执行最多 16 次调用。
暂不支持输入任意服务器命令、远程 URL、凭据或写工具。Skill 内容与 MCP 文档都不能授予额外权限。

关闭连接或撤销 Agent/工具绑定会拒绝后续调用；执行结束、中断、租约失效及 API 重启也会使旧凭据不可用。
`pnpm dev:local` 自动设置正确 API 端口。独立 API 启动且端口不是 8000 时，设置
`AGENTHUB_MCP_GATEWAY_ORIGIN=http://127.0.0.1:<实际端口>`；仅支持本机回环 HTTP。

### 配置与使用 Skills

打开 Agent 目录设置，顶部“Skills · 技能库”提供 React 表单开发、FastAPI 接口修改和代码审查三个内置技能。
点击技能可编辑，或点击“新建技能”后导入 `SKILL.md`。文件包含 YAML 头部的 `name`、`description`
以及 Markdown 操作说明。名称使用小写字母、数字和连字符。选择适用角色，再勾选需要默认使用它的 Agent。
同一技能可以停用；保存检查版本，冲突时先刷新并核对最新内容。

第一版支持说明和文本参考资料：`SKILL.md` 最多 16 KB，最多 8 个位于 `references/` 或 `assets/`
下的文本文件，每个最多 12 KB，整个包最多 48 KB。通过相对 Markdown 链接引用资料；只将直接引用的资料
加载进指令。不执行技能脚本，`allowed-tools` 元数据也不会增加 Agent 权限。

聊天输入区“本次技能”默认继承 Agent 设置，也可明确选择最多 3 个技能（指令合计最多 24 KB），或
“全部取消”让这条消息不使用技能。成功发送后恢复默认选择。群组任务只向适用角色加载相应技能。
执行过程的“技能加载”显示所用来源、版本、指纹及已加载/角色不适用/脚本模式不支持。
“已载入调用指令”不能证明模型遵循了每一条说明，结果仍需查看真实 Diff 和 QA。

每次运行在创建时冻结技能内容，后续编辑不会改变该运行；重试沿用原运行绑定。
重新生成消息保留原显式技能包并绑定新消息身份。旧运行不自动补加载后来配置的技能。

普通聊天支持 Markdown 标题、列表、表格、引用和代码。代码块右上角可单独复制
代码，消息下方可复制完整原文或引用到下一条消息；复制失败会显示提示。宽表格
和长代码在消息内横向滚动。图片链接先显示来源，点击“加载图片”后才请求图片；
部分图片服务不允许跨源匿名加载，可使用“打开图片链接”。若要让 Agent 读取文件
或图片，请使用输入框左侧的“添加附件”，普通图片链接不会自动转成模型图像输入。

消息下方的图钉按钮用于保留后续 Agent 需要参考的约定。置顶后，即使消息已离开
最近 8 条消息窗口，同会话的新规划和执行请求仍会携带它；取消置顶只影响后续
准备的请求，已经启动的运行和保存的历史快照保持不变。

置顶引用优先选择最近置顶的消息，最多 16 条、每条最多 2,000 字符，总量最多
12,000 个 ASCII JSON 序列化字符（以缩进 2 的引用载荷计，中文会占用更多字符）。
过长内容会截断，超出预算的旧引用会省略；请求中的选择记录包含相关数量。
置顶内容仍是会话参考，保留原发送者，不会成为系统指令、可信记忆或工具授权。
凭据赋值和受保护路径会过滤；请将关键约定写得简洁，避免在聊天里粘贴凭据。

## 通过对话创建 Agent

点击聊天侧栏联系人旁的“对话创建”，或进入 Agent 目录并打开创建对话。描述它的
职责、目标和输出偏好；配置助手可以追问，也可以生成可编辑的名称、别名、提示词
和工具设置。直接修改表单后继续补充要求，下一次生成会携带当前手工修改。

此功能使用运行设置里的 Planner。未配置、停用或连接失败时会显示原因，已有草稿
保留；也可以继续使用页面原有手动配置表单。生成配置不执行编码任务或保存 Agent。
检查目标和工具权限后，勾选“启用自定义 Agent”并点击保存，即可返回聊天通过
`@别名` 指派；不勾选则保存为停用状态。系统提示词不会授予超出表单策略的权限。

同一标签页刷新后重新打开创建对话可恢复草稿；关闭标签页可能清除未保存内容。
浏览器存储不可用时有提示。配置助手只参考最近 10 条创建对话与当前草稿；开始
新的创建对话会确认清空未保存内容，不会删除已保存 Agent。

## 引用选中代码继续修改

在“成果 → 代码变更”打开“编辑完整源码 / 应用补丁”，读取完整源码后选中一段
代码，再点击“引用选中代码”。代码编辑器和纯文本模式都支持；单次最多 2400
字符，超过时请缩小选区。片段、目标文件和来源 Diff 会显示在待发送上下文中。
随后输入修改要求并发送，Agent 继续经过原有规划、权限和执行检查。

引用的是编辑器草稿，不会自动写入文件或发送消息；即使草稿尚未应用，也会明确
标记来源。消息最多 8 项上下文，可逐项移除或调整顺序。切换到其他会话会清除
待发送引用，避免把上一会话的代码带到新会话。

## 重新生成回复和汇总

已完成的回复或计划下可点击“重新生成”，阅读说明后确认。系统保留原消息与成果，
追加原请求及附件引用，再使用当前代码、上下文和 Agent 配置处理；可能创建并执行
新的代码任务，已有文件修改不会撤销。来源链接可跳回原消息，执行结果仍看任务卡。
原计划有未完成任务，或会话仍有运行/审批等待时，请先处理原任务；失败运行继续
使用任务的“重试”，无需重复整个请求。

任务组最新已完成汇总下的“重新汇总”只重新解释运行证据，不重跑编码任务；旧汇总
仍可查看。生成未完成时会保留请求及已创建的任务，不将准备成功显示为代码完成。
网络结果不明确时，再次确认会先查找同一操作；页面刷新后仍可从历史查看记录。
服务重启会标记被中断的准备，不会自动重发模型请求。

## 发送文件和图片

点击回形针选择文件，等待“文字已提取”或“图像输入”，再输入任务要求并发送。
支持 UTF-8 文本/常见代码文件、文本 PDF、PNG/JPEG/WebP 静态图片，每条消息最多
4 个附件、单个最多 8 MiB；文本文件另限 512 KiB，PDF 最多 100 页。
图片最多 1200 万像素、单边 10000 像素，输入模型前按方向校正并缩至最长边 2048。
图片预览使用处理后的图像，“下载”保留原文件。

上传或校验失败时不会发送未就绪的附件，错误显示在草稿中，可移除后重新选择。
切换会话时附件草稿保留在原会话；尚未发送的草稿不会跨页面刷新保存，需要重新选择。
每个会话最多 256 个附件、原始文件总计 128 MiB；未发送记录超过 24 小时后在该
会话下次上传时清理。已发送附件保留原文和哈希，不能通过草稿移除操作删除。

文本/PDF 最多提取前 60,000 字符，实际请求再按当前消息、引用消息、置顶消息、
最近消息的顺序选择；单份最多 12,000 字符，文本与来源记录总预算为 24,000 个
ASCII JSON 序列化字符。图像最多 4 张且处理后总计不超过 8 MiB。超出预算会
记录截断或省略，置顶也不会绕过预算。附件是参考数据，不增加工具或文件权限。

扫描 PDF 若提取不到文字会明确提示；当前没有 OCR，需另传文字版 PDF、文本，
或用支持图片的原生 Agent 读取截图。脚本兜底不会解读任意附件。
Codex 原生文件/图片输入已实测；Claude 文件文本输入也已实测，但本机当前 Claude
配置背后的模型拒绝图片。只有模型和提供方确实支持视觉时，图片任务才可能成功；
不能只看 CLI 名称判断模型能力。若规划失败但消息已保存，界面会保留消息和附件，
清除已发送草稿并显示原因，可引用该消息交给支持相应输入的 Agent 继续处理。

## 首次准备

需要 Git、符合 `package.json` 范围的 Node（20.19+ 的 20.x、22.12+ 的 22.x 或
24+）、pnpm 10.33.4 和 Python 3.11+。从 Git 检出仓库；会话依赖 Git worktree，
仅复制源码 ZIP 不满足这个运行条件。

在仓库根目录明确安装依赖。Windows PowerShell：

```powershell
pnpm install
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r apps/api/requirements.txt
pnpm demo:setup
```

macOS / Linux 的 Python 两条命令改为：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r apps/api/requirements.txt
```

启动器不会安装或更新依赖。`pnpm-workspace.yaml` 已限制允许执行构建脚本的包，
保留该列表。演示应用依赖用于 Session 预览，必须在准备阶段安装。

## 启动、端口和退出

```powershell
pnpm doctor:local
pnpm dev:local
```

doctor 只检查本地 Node、Git、Python/包和选定端口，不导入业务应用、不初始化
SQLite、不访问模型。启动器启动 API，再启动 Web；日志中的 `[local] Ready:`
表示自有进程就绪并且 HTTP 检查通过。默认地址为：

| 服务 | 地址 | 用途 |
| --- | --- | --- |
| Web | http://127.0.0.1:3000 | 编程工作台 |
| 产品 API | http://127.0.0.1:8000 | 会话、调度、SSE 与制品 |
| 可选 demo API | http://127.0.0.1:5174 | 仓库内置 FastAPI 示例服务 |
| Session Preview | 界面返回的本地端口 | 实际 Session 工作树中的 Vite 页面 |

端口占用时启动器会失败，不接管或关闭其他监听服务。产品端口可改：

```powershell
pnpm doctor:local --api-port 8001 --web-port 3001
pnpm dev:local --api-port 8001 --web-port 3001
```

也支持启动终端的 `AGENTHUB_API_PORT`、`AGENTHUB_WEB_PORT`；命令行参数优先。
启动器同步设置 Web 的 `BACKEND_URL` 和产品 API 的
`AGENTHUB_FRONTEND_ORIGIN`。端口必须在 1024–65535、互不相同，并避开已知浏览器
受限端口；建议使用 8000/8001 和 3000/3001。所有服务只绑定 `127.0.0.1`。

```powershell
pnpm dev:local --demo-api
```

可选 demo API 固定使用 5174，与内置目标契约保持一致。它启动仓库的
`apps/demo-api`，不能据此认定某个 Session 的后端修改已经生效。网页结果应从
关联 TaskRun 的 Diff/Preview 判断。统一入口不会另外启动根目录的 Vite Demo，
Preview 仍由后端按目标、依赖、作用域及评审门禁管理。

在启动终端按 **Ctrl+C** 正常退出。通过管道运行时，输入 `stop` 或关闭输入管道
也会退出。启动失败或任一自有服务退出时，启动器会清理已启动的其他服务。
正常退出给 API 执行 lifespan 清理的时间，停止它拥有的 Preview，再处理超时进程。
已有会话和工作树保留；不会运行 `demo:reset` 或删除数据库。

Windows 下已针对连接关闭时的一个已确认 10054 清理失败补全资源释放。若日志出现
`Recovered Windows peer-reset connection cleanup (10054).`，表示该连接的遗留清理
已完成；它不表示 Agent 失败，也不表示重新执行了模型任务。其他异常仍会上报。
退出超时或清理错误应保留日志并核对自有进程，不能仅凭监听端口关闭判断退出完成。
实测范围及对照证据见 [连接清理验收](windows-connection-cleanup-review.md)。

强杀启动器、断电或关闭终端可能跳过正常退出，不能保证全部子进程即时消失。
下次启动若报告端口占用，先确认该端口进程的归属，再自行停止。对于失去归属的
旧 Preview，后端不会信任或终止旧 PID，界面显式重启会创建新的受管 Preview。

统一入口不启用 API/demo API 自动 reload，修改 Python 源码后请重启。
开发时可保留旧方式：`pnpm dev:api` 与 `pnpm dev:web` 分别运行，旧后端命令
需要 Bash（Windows 可使用 Git Bash）。若单独改变 API 端口，还要在启动 Web 的
终端设 `BACKEND_URL`；改变 Web 端口要相应设置 `AGENTHUB_FRONTEND_ORIGIN`。
同一 checkout 的 Next dev 使用同一 `.next/dev` 锁，不能同时运行两个 Web 实例。

## 数据与 Agent 配置

首次 API 启动自动建表并初始化本地用户/工作区/Agent，首次会话由用户创建。
后续启动复用 SQLite 并执行已有的增量初始化。默认库位于
`apps/api/data/agenthub.sqlite3`；会话工作树位于仓库 `.worktrees/`。

Python 环境按显式 `AGENTHUB_PYTHON_BIN`、本 checkout `.venv`、主 checkout
共享 `.venv`、激活的 Conda 顺序选择。显式路径无效时直接报错，例如：

```powershell
$env:AGENTHUB_PYTHON_BIN = 'C:\Python312\python.exe'
pnpm doctor:local
```

这只是路径示例，需要替换成实际已安装且装有 requirements 的解释器。
`apps/api/.env` 可配置 `app/config.py` 中的 Settings，例如
`AGENTHUB_DATABASE_URL`；终端环境变量优先。其他运行时变量不要仅写入这个
`.env` 后就假定已生效，应按其源码读取方式设置启动环境或界面配置。

工作台左下“工作区设置”提供：

- **联系人设置 / Agent 目录**：修改名称与别名、创建受限 Agent 档案、查看能力。
- **运行设置**：为 Planner、Frontend、Backend、Review 选择档案、Provider、模型和
  System Prompt（系统提示词），保存后使用提供方检查。新 TaskRun 冻结当次配置。
- **记忆设置**：工作区/会话规则、偏好与内容快照；已有 Session 需显式刷新快照。

真实编码需要本机 Codex 或 Claude Code CLI 可用且已完成用户自己的鉴权。
自定义 CLI 路径分别使用启动环境的 `CODEX_CLI_PATH`、`CLAUDE_CODE_CLI_PATH`。
`AGENTHUB_DEFAULT_CODE_ADAPTER=claude_code` 是未被工作区配置覆盖时的编码默认值；
Planner、评审、汇总以各自配置与运行快照为准。doctor 的依赖通过不代表真实
Provider 已鉴权或模型可用；它不会执行 CLI/模型探针。

密钥保留在本机受保护配置或终端环境，不能提交到 Git。启动器把后台配置传给
产品 API；传给 Web 和 demo API 的父终端环境限于系统及显式公开的变量，Web
额外获得本地 `BACKEND_URL`。不要把密钥放进 `NEXT_PUBLIC_*` 等公开变量。

## 完成一次可检查的任务

1. 新建 Session，选择目标，在群聊发送 `@orchestrator build a login page for the demo app`。
2. 默认自动组展示规划、角色任务、依赖和运行状态；历史手动计划需要逐项启动。
   单 @ 或多个 @ 可以明确指定已有别名，实际执行仍受档案、工具与目标范围限制。
3. 查看“执行过程”的 DAG（依赖图）、事件和来源；查看“成果”的真实 Diff、评审与
   Preview。Preview 需要满足门禁并点击启动/恢复；生成的按钮或表单应在实际网页中验证。
4. 在同一 Session 请求一处小修改，再检查新运行和关联制品。累计 Session Diff
   不等于单次独立 patch；以运行来源和文件版本判断。
5. 使用亮暗切换、两侧拖动边界、会话搜索/置顶/归档和关键消息置顶整理历史。
   归档会话不等于取消执行。

TaskRun 执行完成、模型评审通过和网页功能验证是不同证据。ScriptedMock 能
修改真实演示文件并走相同 Diff/Preview 路径，但不会执行模型提示词。脚本评审
不等于模型原生评审；部署卡也不代表已经生产上线。

### 查看分项 QA 结果

新生成的评审报告分别显示规则检查、模型评审，以及静态检查/测试/构建的命令记录。
“QA 待验证”表示证据尚不完整；“QA 有阻塞问题”表示规则、模型或命令记录存在失败。
模型的通过结论不能覆盖规则失败，本地 staging 也会拒绝有阻塞问题的报告。

模型评审继续通过运行设置选择已有的 Claude 只读评审档案；脚本报告不会自动调用模型。
没有模型结果时明确显示未运行。Vite 演示前端的新运行会在完成前自动执行固定验证流程：

1. 在临时源码副本中运行 TypeScript 类型检查。
2. 使用平台持有的 Vite/React 配置构建，不执行 Agent 修改过的配置或 package scripts。
3. 运行 3 项构建产物冒烟测试：React 挂载入口、引用资源存在且非空、生产 JS 与源码入口检查。

不安装依赖；类型检查缓存和构建输出都留在临时副本中。每个命令超时上限 60 秒，
前一步失败就停止，不拿旧产物跑测试。任务中断会停止验证进程；失去执行权后不发布成功。
启动和结果保存在 TaskRunEvent，记录同一运行/执行代次、源码与策略指纹、退出码和有限日志。
重启后遗留的 running 记录不会被补成成功，需显式发起新的运行。

报告面板显示绑定版本、源码指纹与日志。只有规则、原生模型评审、全部自动命令通过且版本一致，
才显示“本版本已配置验证通过”；脚本路径仍显示模型未运行。源码、锁文件或验证策略变化后，
重新读取报告会显示已过期/无法核对，本地 staging 拒绝使用这类绑定证据。历史快照不被改写。

上述三步只覆盖构建产物；指定需求的交互验收见下一节，均不代表完整业务验收。当前自动执行仅支持
原生配置一致的 `demo-frontend`；外部项目及其他目标仍保留未验证状态。已有依赖与平台工具链
属于本地可信环境，这不是通用 OS 沙箱。手工补录的命令仍只显示“记录通过”，不能建立版本验收；
报告不混用其他运行或后续补录的测试，旧报告不会被自动升级。

### 查看需求交互验收

Vite 演示前端的三种结构化任务已接入真实浏览器验收：

| 任务目标 | 验收内容 |
| --- | --- |
| `login_page` | 桌面/390px 窄屏下输入可见且有标签；空邮箱、空密码和非法邮箱不能提交；有效输入能触发提交 |
| `demo_heading_text` | 指定标题可见且文案一致（按页面空白折叠规则比较） |
| `primary_action_button_text` | 指定按钮可见、文案一致且能实际点击 |

这些任务在 Agent 启动前冻结验收目标与期望文案（最多 256 字符），构建/冒烟测试通过后，
由平台维护的 Playwright 脚本检查临时构建产物。页面运行错误、缺失资源、外部请求或弹窗
会使检查失败。验收过程中使用演示输入并拦截提交，不发送账号认证请求；脚本登录表单
自身也阻止默认提交，并明确显示演示用途。它不提供真实登录成功或后端接口验收。

浏览器使用独立临时配置，不使用个人浏览器标签页、Cookie 或登录状态；HTTP/WebSocket
请求受到拦截，仅提供当前临时产物。产物不通过本地监听服务暴露。这是有限的本地浏览器
验收，不是通用恶意代码隔离环境。

QA 面板新增“需求交互验收”，可展开查看桌面/窄屏分项、失败原因和期望文案。
规则、模型、构建验证和需求验收全部通过时，显示“本版本指定需求验收通过”。模型未运行、
浏览器不可用或需求未覆盖都会明确保留，不用冒烟测试成功替代交互验收。修改源码、期望文案
或验证策略后，重新读取报告会标记过期；历史分项是原运行记录，不代表当前版本。

浏览器准备只在开发环境安装阶段进行：根目录 `pnpm install --frozen-lockfile` 会安装固定的
Playwright 开发依赖。Windows 默认使用已安装的 Edge；Linux 默认使用 Playwright Chromium，
需事先执行 `pnpm exec playwright install chromium` 并准备系统依赖及沙箱支持。
CI 固定使用 Ubuntu 24.04 镜像预装的 Chrome（显式 `chrome` channel），测试前先检查沙箱启动与页面渲染。
这避免下载版 Chromium 与主机 AppArmor 策略不兼容；不关闭浏览器沙箱或修改主机的全局安全策略。
可用 `AGENTHUB_VALIDATION_BROWSER_CHANNEL=chromium`、`msedge` 或 `chrome` 选择已有浏览器；
任务执行不会安装或下载。浏览器无法启动时显示环境不可用，并区分已识别的浏览器缺失、沙箱不可用、
配置错误或执行中断；诊断只返回固定分类，隐藏原始启动参数和主机路径。修复环境后发起新运行。
未知或没有明确 `target` 的任务不会根据网页内容猜测验收目标，显示“未覆盖此需求”。

## 故障恢复与备份

| 情况 | 操作与边界 |
| --- | --- |
| Python/包缺失 | 按首次准备明确安装，或选择正确的已有环境；启动不会替你安装 |
| 端口占用 / Next dev 锁冲突 | 停止已确认归属的旧服务；产品端口可改，Next 同 checkout 锁仍共享 |
| CLI 不可用、鉴权或模型失败 | 看运行错误、校验提供方配置；可重试或显式选择脚本兜底，保留失败来源 |
| 任务中断 | 查看中断/租约状态后显式重试；不能把 SSE 重新连接当成模型自动续跑 |
| Preview 失去归属/进程退出 | 点击重启；继续保留旧制品来源，未合并结果不解锁预览 |
| 页面断线/刷新 | SSE 使用持久游标补读事件，界面重新读取 Session；历史保存在 SQLite |

直接/确定性组的有界登录页需求现在保存明确目标，例如
`@frontend build a login page for the demo app`、
`@frontend @qa build a login page for the demo app`；Orchestrator 英文与中文创建
均可使用原有三步计划。新 ScriptedMock 登录模板还生成受控样式块，提供灵活输入宽度、
字段间距、自动填充属性和可见键盘焦点，保留其他 CSS。支持的按钮文案后续修改只写
App 并保留表单/样式，仍需通过既有工作树和完成门禁；累计 Diff 可以包含前序 CSS。
支持的规范化按钮/标题文案中的花括号、标签或实体拼写现在按纯文本渲染，普通文案
保持原有格式，后续修改仍可继续定位。此项不扩展原有文案解析长度或请求语法。
OAuth/JWT/服务端认证等额外要求不属于脚本登录模板，显式兜底仍会诚实失败。
语言/检查/日志流程附注保留原文，不扩展文件权限，也不代表脚本执行了这些步骤。
旧泛化 plan 和失败历史不自动改写，需要重新规划时在新 Session 发送有界需求。
运行中的旧后端需正常重启以加载新规划与模板，历史成果不会被自动改写。
详见 [目标验收](login-fallback-target-binding-review.md) / [样式验收](scripted-login-form-styling-review.md) /
[字面量验收](scripted-copy-literal-rendering-review.md)。

输出完成前仍需检查整个工作树，耗时随文件量和机器负载变化。内部重复采集已
减少一次，相关文件/锁/完成检查保留；本地固定样本和验证边界见
[输出核验性能记录](scope-finalization-performance-review.md)。

备份前正常停止产品服务，保留 SQLite（如有同名 `-wal`/`-shm` 文件一起保留）、
会话 `.worktrees/`、Git 主仓库以及受保护的本地配置。工作树的 `.git` 引用主仓库，
只复制 SQLite 或单个工作树不能完整还原工作区。不要为解决启动问题运行重置命令。

工程验证使用 `pnpm check`、`pnpm test:local`、`pnpm test:web`、`pnpm test`。
仓库含受版本管理的依赖补丁；按锁文件复现使用
`pnpm install --frozen-lockfile --ignore-scripts`。`pnpm test:local` 同时检查启动器和
实际依赖链中的深度保护。完整审计保留 braces 的 1 条上游告警，本地缓解与版本说明见
[依赖安全记录](local-dependency-security-review.md)；不要手动改 `node_modules` 或屏蔽告警。
Diff 的并排查看现在使用本地 Monaco 和 worker，无需从 CDN 下载编辑器；
加载失败时仍可查看补丁，并点击“重试加载”。
在成果面板打开代码变更，选择“编辑完整源码 / 应用补丁”。先读取当前文件，
修改后点击“检查并生成差异”，核对补丁和版本后再点击“应用以上差异”。准备阶段
不改文件；已有 Agent Diff 是历史证据。也可输入同一目标内的 UTF-8 统一 Diff，
支持修改、增添和删除文件；增添文件的父目录必须已存在。

本功能限定服务器分配的规范 Session 工作树与允许目标，不支持直接编辑外部主机目录、
平台文件、链接、二进制、重命名或权限变更。单次最多 16 个文件，补丁 2 MiB，
单文件 512 KiB，修改前后内容合计 4 MiB。执行或持锁期间不能应用。
发生冲突时保留草稿，重新读取后再生成新差异；请求失败可重试同一记录，避免重复写入。
成果面板的“用户修改记录”保留最近 50 项操作，浏览器草稿仅在当前标签页内恢复。

中断后若结果不明确，会暂停该会话后续执行。先核对当前文件，再明确选择保留当前
文件并恢复执行；这一步不会写文件，也不会把部分修改标记为完整应用。应用成功
只证明写入成功，需另外检查页面和测试；旧评审不能验证新修改。后续 Agent 的 Diff
以执行前实际内容为基线。长 Claude Planner 续接通过标准输入传递，避免 Windows
命令行长度限制；原有工具权限和无会话持久化约束不变。
当前后端检查/测试包装仍要求 Bash；本次真实启动验证另见
[本地启动验收记录](local-startup-entrypoint-review.md)。
