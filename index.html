01 · Overview

把 AI 编程从“回答”推进到“交付”

AgentHub 的核心不是增加更多聊天角色，而是建立从需求理解、任务编排、受控执行到结果验证的工程工作流。

⌁

任务编排

Planner 解析用户意图与角色提及，Orchestrator 生成 Task Graph，并对依赖、角色与 Target 进行组织。

planning.py · task_graph_builder.py
⚙

运行时路由

ProviderGateway 将 Agent 角色与具体 Coding Provider 解耦，统一处理 Provider 解析、健康检查与运行配置。

provider_gateway.py · runtime config
⑂

隔离与并发

Session 级 Git Worktree 提供工作区隔离，Session Queue 与 Target Lock 控制写任务的安全执行顺序。

session_queue.py · target_locks.py
✓

可验证交付

执行结果沉淀为 Diff、Review、Preview、TaskRunEvent 等工程产物，前端持续展示真实运行过程。

diffs.py · previews.py · events.py

一条请求如何进入执行系统

从 IM Session 进入 Planner，再经过任务图、Scheduler、运行时路由和受控工作区，最终生成持久化事件与可检查 Artifact。

Planning规划层Planner、Orchestrator、Task Graph：把自然语言需求转换成可执行工程任务。
Execution执行层TaskRun、Scheduler、ProviderGateway：决定任务什么时候执行、由谁执行。
Isolation隔离层Git Worktree、Target Scope、Target Lock：控制工作目录和写入边界。
Evidence证据层Diff、Review、Preview、TaskRunEvent、SSE：让执行结果可检查、可追踪。
03 · Engineering

工程设计重点

项目把多 Agent 协作拆成规划、运行时、隔离、并发与证据模型几个独立问题，避免把所有职责塞进一个“Orchestrator 类”。

01 / TASK GRAPH

任务不是聊天消息，而是可调度节点

  • Task 记录角色、Target、依赖与 Intent。
  • 任务图校验后再进入 Scheduler。
  • 前置任务完成后，下游任务才能进入可运行状态。
planning.py · plan_validator.py · task_graph_builder.py
02 / PROVIDER RUNTIME

角色职责与具体模型 / CLI 解耦

  • ProviderGateway 根据 role / target / capability 做运行时解析。
  • 统一处理 Provider 健康、容量与 Adapter 能力。
  • Planner 和 TaskRun 不需要绑定某一个 Coding CLI。
provider_gateway.py · codex_adapter.py · claude_code_adapter.py
03 / ISOLATION

Worktree 隔离会话，Lock 控制写冲突

  • 不同 Session 在独立 Git Worktree 中工作。
  • 写任务通过 Session Queue 控制运行顺序。
  • 同一 Target 使用写锁建立互斥边界。
session_queue.py · scheduler.py · target_locks.py
04 / EVENT MODEL

执行过程先持久化，再实时投影到前端

  • Adapter 事件标准化为 TaskRunEvent。
  • 事件落 SQLite 后通过 SSE 增量推送。
  • Diff、Review、Preview 与 Diagnostics 统一形成证据链。
events.py · run_engine.py · run_diagnostics.py
04 · Evidence

执行结果必须可追踪、可检查

AgentHub 不把“模型说完成了”视为最终结果，而是继续采集真实代码变化、运行状态与前端预览，形成工程交付证据。
