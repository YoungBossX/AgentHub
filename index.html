01 · Overview

从一条需求，走到可检查的代码结果

围绕真实代码任务组织协作：先明确目标与依赖，再受控执行，最后核对 Diff、检查和预览。当前是本地单用户工作台，保留真实模型与脚本兜底的来源区别。

03 · Engineering

工程设计重点

围绕四个问题设计：任务怎样拆解，角色怎样选择运行时，代码修改怎样隔离，以及结果怎样按当前版本核对。Skills、MCP、记忆和用量观测沿用这些边界。

01 / TASK GRAPH

先校验计划，再按依赖执行

  • Task 记录角色、目标、依赖与意图，TaskRun 记录每次尝试。
  • 讨论、澄清和拒绝不伪装成执行；计划校验后才进入调度。
  • 前置失败保留阻塞原因；中断和重试保留原始运行记录。
planning.py · plan_validator.py · task_graph_builder.py
02 / PROVIDER RUNTIME

配置可复用，执行仍然受控

  • ProviderGateway 按角色、目标与能力选择兼容运行时。
  • 配置和提示词进入运行快照，后续修改不改写历史。
  • Skills 补充说明；兼容 Codex 的内置 MCP 只读项目文档，不扩大权限。
provider_gateway.py · codex_adapter.py · claude_code_adapter.py
03 / ISOLATION

隔离工作目录，限制写入范围

  • 不同会话使用独立工作树，任务仅操作分配的目标。
  • 默认写任务经 Session Queue 与 Target Lock 控制顺序及互斥。
  • 可选 Docker 只承载固定检查与测试；Agent CLI 和预览仍原生运行。
session_queue.py · scheduler.py · target_locks.py
04 / EVENT MODEL

事件可恢复，用量与耗时可追溯

  • 标准化事件先写入 TaskRunEvent，再通过 SSE 增量展示。
  • Session 游标、心跳与重放支持断线后恢复显示。
  • 记录可获得的 Token 回执和阶段耗时，缺失用量保持未知。
events.py · run_engine.py · run_diagnostics.py

05 · Stack & Modules

技术栈与核心模块

前端采用 Next.js / React，后端采用 FastAPI / SQLModel，SQLite 由 Alembic 管理版本。SSE 推送运行事件；Docker 是可选固定验证后端，不依赖 PostgreSQL、Redis 或 WebSocket。
