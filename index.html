01 · Overview

把 AI 编程从“回答”推进到“交付”

AgentHub 的核心不是增加更多聊天角色，而是建立从需求理解、任务编排、受控执行到结果验证的工程工作流。

⌁

任务编排

Planner 解析用户意图与角色提及，Orchestrator 生成 Task Graph，并对任务依赖、角色和 Target 进行组织。

⚙

运行时路由

通过 ProviderGateway 将角色职责与具体 Coding Provider 解耦，统一处理 Provider 解析、健康检查与运行配置。

⑂

隔离与并发

Session 级 Git Worktree 提供代码工作区隔离，Session Queue 与 Target Lock 控制写任务的安全执行顺序。

✓

可验证交付

执行结果沉淀为 Diff、Review、Preview、TaskRunEvent 等工程产物，前端能够持续展示真实运行过程。

03 · Engineering Design

核心工程设计

围绕多 Agent 同时修改代码、Provider 差异、长任务可观测性和结果验证，形成明确的运行时边界。

Isolation & Concurrency

Git Worktree + Queue + Target Lock

  • 不同 Session 绑定独立工作区，避免会话之间互相污染。
  • 只读任务可并行执行，写任务按照 Session Queue 管理执行顺序。
  • Target Lock 对共享写目标建立互斥边界，RunEngine 统一管理执行生命周期。
session_queue.py · target_locks.py · run_engine.py
Runtime Abstraction

ProviderGateway + Adapter

  • 角色配置与具体模型/CLI 解耦，运行时根据 role、target、capability 解析 Provider。
  • Provider 健康、容量与执行上下文集中在 Gateway 层管理。
  • Adapter 将 Codex CLI、Claude Code CLI 等执行方式统一到一致的 Agent 事件接口。
provider_gateway.py · codex_adapter.py · claude_code_adapter.py
Traceability

TaskRunEvent + SSE

  • Agent 执行过程标准化为事件，并持久化为 TaskRunEvent。
  • 前端通过 SSE 按事件增量更新任务状态、执行轨迹和产物。
  • 持久化事件可继续用于会话恢复、执行回放和运行诊断投影。
events.py · models.py · workspace-shell.tsx
Verification

Diff + Review + Preview

  • 执行后采集真实 Git Diff 或文件快照差异，展示实际代码变更。
  • Review Artifact 对变更进行独立审查，Preview Service 启动本地前端验证。
  • 统一 Artifact 模型把代码差异、审查结果和预览状态组织为交付证据。
diffs.py · reviews.py · previews.py · artifact_*.py

Delivery Pipeline
Plan

将用户需求拆解为带角色、Target 与依赖的任务图。

Route

根据运行时配置和能力要求选择执行 Provider。

Guard

检查队列、写锁与工作区范围，建立执行边界。

Execute

Adapter 在分配的 Worktree 或 Target 中完成代码操作。

Verify

采集 Diff、Review 与 Preview，形成可检查工程产物。

Observe

TaskRunEvent 持久化并通过 SSE 投影到前端工作台。
